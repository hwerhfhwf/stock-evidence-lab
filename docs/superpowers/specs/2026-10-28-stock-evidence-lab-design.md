# Stock Evidence Lab 设计说明

## 意图

面向需要快速理解单只 A 股但不愿被“综合评分”误导的个人投资者与投研人员，提供一条从问题到诊断、再到原始证据的主链路。首个演示标的是美的集团（000333），数据快照以公开的 2025 年报与 2026 半年报为主。

## 目标

- 根据公司类型与用户问题自动选择诊断维度。
- 同屏表达正面、负面、矛盾与未知证据，不输出买卖建议。
- 每个关键数字注明期次、单位、来源、口径并可钻取。
- 确定性计算由规则引擎完成，语言模型仅负责问题路由、摘要与待验证问题。
- 在数据缺失或接口失败时明确降级，不静默生成正常结论。

## 非目标与反目标

- 不做实时交易终端，不承诺实时行情。
- 不预测涨跌、不提供目标价或确定性收益判断。
- 不用一个总分掩盖维度间矛盾。
- 不把公司自述、媒体转述和法定披露视为同等证据。

## 约束

- 24 小时作业场景，优先可运行、可部署、可审计。
- 不提交 API Key；扶摇/iFinD 通过后续数据适配器接入。
- 静态快照必须明确“截至 2026-08-28 披露的 2026H1 数据”。

## 方案

1. 重后端实时版：覆盖面最高，但受 API 授权、限频和部署密钥阻碍，不适合作为 24 小时首版。
2. 纯视觉静态页：最快，但无法证明主链路、异常处理和 AI/计算分工。
3. **可交互证据快照 + 可替换数据适配层（采用）**：用真实公开快照完成完整体验，接口边界清晰，可在获得扶摇/iFinD 权限后替换数据源。

## 体验

用户输入研究问题，系统识别问题意图并突出相关维度；首页以“证据温度计”展示四类证据计数，而非总分。诊断卡展示事实、规则计算、解释和证据来源。点击卡片打开证据抽屉，可查看原始字段、公式、期次、来源与仍待验证的问题。用户可以切换“正常 / 数据缺失 / 接口失败”三种场景验证降级行为。

## 实现边界

- 原生 HTML/CSS/ES Modules，零运行时依赖。
- `src/engine.mjs`：确定性计算、证据分类、问题路由与降级。
- `src/data.mjs`：美的集团公开数据快照及来源链接。
- `src/app.mjs`：视图和交互，不承担金融计算。
- Node 内置测试覆盖计算、路由、缺失和失败场景。
